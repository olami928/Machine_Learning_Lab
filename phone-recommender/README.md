# Naija Phone Finder — Smartphone Recommendation System for the Nigerian Market

A small, explainable recommendation system that matches Nigerian smartphone
buyers to phones based on budget, primary use, and priorities — then ranks
them with either a transparent rule-based scorer or a distilled ML model.

## Why two engines?

I started with an interpretable rule-based recommendation system because I
didn't have real customer interaction data to justify a machine-learning
recommender. Then I generated a synthetic customer population, used the
rule-based scores as training labels, and distilled a Random Forest from
them (R²=0.966 on held-out customers). The architecture is built so the
scoring layer can be swapped for a model trained on real interaction data
later, without touching data loading, explanations, or the UI.

**Both engines are honest about what they are:**
- Rule-based: fully transparent, hand-set weights (Budget 30%, Camera 20%,
  Battery 20%, Performance 15%, Storage 10%, Brand 5%), reshaped per
  customer's primary use and priorities.
- ML: a Random Forest trained on the rule-based scorer's own output over
  600 *synthetic* customers — a distillation model, not one trained on real
  user behavior. It's flagged as such in the app and in the code.

## Data

- `data/phone_catalog_ng.csv` — 63 real, individually sourced phones across
  8 brands (TECNO, Infinix, Samsung, itel, Xiaomi/Redmi, Oppo, Google Pixel,
  Apple), with `price_source` and `price_verified_date` on every row. Where
  a spec couldn't be verified, the cell is left blank rather than guessed.
- `data/synthetic_customer_preferences.csv` — 600 synthetic buyer profiles,
  explicitly labeled `data_source: synthetic`. Not real survey data.
- `data/training_data.csv` — ~14K (customer × in-budget phone) scored pairs
  used to train the ML model.

## Project structure

```
smartphone_recommender/
├── data/
│   ├── phone_catalog_ng.csv
│   ├── synthetic_customer_preferences.csv
│   └── training_data.csv
├── src/
│   ├── data_processing.py      # load + clean catalog
│   ├── scoring.py               # transparent weighted scoring components
│   ├── recommender.py           # rule-based top-3 + explanations + diversity
│   ├── generate_customers.py    # synthetic customer generator
│   ├── build_training_data.py   # distills rule-based scores into training rows
│   ├── train_model.py           # trains + evaluates the Random Forest
│   ├── ml_recommender.py        # ML-based top-3, same explanation layer
│   └── ml_model.joblib          # trained model (generated by train_model.py)
├── app.py                       # Streamlit UI
├── requirements.txt
└── README.md
```

## Running it

```bash
pip install -r requirements.txt

# (only needed if ml_model.joblib is missing/out of date)
python src/generate_customers.py
python src/build_training_data.py
python src/train_model.py

streamlit run app.py
```

## Known limitations

- Catalog covers 63 of the ~120 targeted phones — several current models
  simply have no publicly confirmed Naira price yet, and were left out
  rather than estimated.
- Pixel and Oppo pricing reflects gray-market import listings, since
  neither brand officially retails in Nigeria — flagged in `price_source`.
- The ML model is distilled from the rule-based scorer, not real purchase
  or click data. Treat its R² as "faithfully reproduces the rule logic,"
  not "predicts real customer behavior."
